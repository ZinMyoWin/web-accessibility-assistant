# Frontend documentation coverage ledger

This ledger compares the current `frontend/` source inventory with the documentation produced in this audit. It is a navigation and follow-up tool, not a claim that the application has been fully audited or that tests pass. The status describes **documentation depth**, not correctness, implementation completion, or verification.

- **Function reference:** a guide explains named functions or significant callbacks, their role, and selected inputs, outputs, effects and failures. It does not imply every branch or caller was checked.
- **Summarized:** a guide explains purpose, composition or selected interactions, but not each function, prop, branch, or error path.
- **Pending:** identified code or behavior has not received the requested detailed treatment. A folder can have more than one status when different parts have different coverage.
- **Excluded:** generated, third-party or sensitive material intentionally outside this documentation inspection; this does not mean it is safe or unnecessary.

This is a working-tree snapshot. Recheck paths and behavior after code changes. Documentation links below are relative to this file.

## Explicit exclusions and follow-up

- **Sensitive configuration:** environment files and their values were not opened or copied. References to configuration variable *names* in project-owned source are not verification of actual settings.
- **Generated/runtime output:** dependency lockfile contents, `next-env.d.ts`, `.next/`, build caches, `node_modules/`, TypeScript incremental state, `test-results/`, `playwright-results/`, `playwright-report/` and coverage output were not audited as authored feature code. Some paths may not exist in a given checkout. The lockfile is operationally relevant and still needs dependency/security review when appropriate.
- **Third-party code:** Next.js, React, NextAuth, Radix, Playwright, Vitest and other installed dependencies were not audited internally. The bundled backend axe asset is third-party and is outside this frontend source review.
- **Dynamic behavior:** callbacks registered through JSX props, effects, timers, NextAuth, MCP tools/resources/prompts and route handlers need branch-specific and integration verification even where the owning function is described. Do not mark every callback complete based on its folder's summary.
- **Next work:** deepen the MCP function/schema reference, trace mock-data exports and all type contracts, inspect remaining inline callbacks and component branches, then compare documentation with actual tests and run only checks consistent with the user's constraints.
